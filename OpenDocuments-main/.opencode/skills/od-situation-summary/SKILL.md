# Ситуационная сводка для OpenDocuments

## Назначение

Генерирует готовый к копированию промпт-запрос на русском языке для платформы OpenDocuments (RAG). Запрос заставляет RAG-платформу превращать сухие корпоративные документы (должностные инструкции, регламенты) в краткие сводки на языке обычного сотрудника.

Запрос чинит 4 боль:

1. **Потеря контекста** — сотрудник мыслит ситуациями («меня вызывают в суд — оплачивается?»), а документ — категориями. Сводка должна отвечать на вопрос «что делать, когда наступила ситуация X?».
2. **Языковой барьер** — убрать канцелярит («во исполнение», «в порядке, установленном»), сложные конструкции из 3–4 придаточных.
3. **Динамика и слепые зоны** — явно показывать пересечения/противоречия со смежными документами.
4. **Информационный шум** — 1 страница (или 1 абзац) на документ вместо десятков страниц.

## Когда использовать

- Пользователь просит «сделай сводку по документам», «преврати в краткое резюме», «сделай скилл/промпт для OpenDocuments».
- Пользователь называет конкретные документы (названия, ID, номера ДИ) из папок `source/` или базы OpenDocuments.
- Пользователь просит подготовить запрос, который можно вставить в чат/поиск OpenDocuments.

## Как действовать

1. Если пользователь назвал целевые документы — собери их список (название или ID). Если нет — попроси уточнить или подставь плейсхолдер `<список документов>`.
2. Собери готовый промпт по шаблону ниже, подставив список документов.
3. Выведи промпт целиком одним блоком для копирования. Не обрезай и не пересказывай его своими словами.
4. Если пользователь просит сохранить — запиши промпт в файл (например `prompts/od-situation-summary.md` или рядом с `source/`). Без запроса файлы не создавай.

## Шаблон промпта для OpenDocuments

Скопируй нижеследующий текст в ответ, заменив `<список документов>` на ФИО/название/ID документов из базы:

```
У меня есть база корпоративных документов в OpenDocuments. Преврати перечисленные ниже документы в краткие сводки на языке обычного сотрудника.

Документы: <список документов>

Для каждого документа дай:
1. Суть роли (или назначение документа) — 1–2 предложения: за что отвечает человек/раздел в целом.
2. «Когда что делать» — 3–6 типичных рабочих ситуаций в формате: ситуация → действие. Говори так, как думает сотрудник («меня вызвали…», «кандидат выбран…»), а не категориями документа («исполнение государственных обязанностей с отрывом от производства»).
3. Требования — образование, стаж, ключевые навыки.
4. Подчинение — кому подчиняется, кем руководит.
5. За что отвечает — простыми словами (риски, ответственность).
6. Пересечения и противоречия — если норма пересекается, уточняется или конфликтует с другим документом из базы (особенно с более высокой юридической силой), укажи это явно со ссылкой на оба документа.

Правила:
- Пиши простым языком, без канцелярита и оборотов «во исполнение», «в порядке, установленном». Один абзац — одна мысль.
- Не пересказывай документ дословно — переформулируй так, как говорит живой человек.
- Держи сводку в пределах одной страницы на документ. Если суть занимает один абзац — не добавляй воды.
- Отвечай на русском языке.
```

## Пример использования

Пользователь: «сделай промпт для OpenDocuments по ДИ-11-993 и ДИ-11-948»

Ответ: промпт из шаблона, где `<список документов>` заменён на:
`ДИ-11-993 (Главный специалист, отдел подбора и адаптации персонала), ДИ-11-948 (Начальник отдела подбора и адаптации персонала)`

## Анти-примеры (чего не делать)

- Не переводить промпт на английский — корпоративная база и сотрудники русскоязычные.
- Не заменять шаблон пересказом про «суммаризацию в целом» — нужен именно готовый промпт.
- Не выводить сокращённую версию или «основное из промпта» — запрос должен копироваться целиком.
