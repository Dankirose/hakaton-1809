## 2. Парсер legacy Word (.doc)

Проблема: `.doc` (OLE/Composite Document) не поддерживался ни одним плагином (есть только `.docx` через mammoth).

Решение — собственный плагин `plugins/parser-doc`:

- Файлы:
  - `plugins/parser-doc/package.json` — зависимости `word-extractor@^1.0.4`, devDep `@types/word-extractor@^1.0.6`.
  - `plugins/parser-doc/src/index.ts` — класс `DOCParser` (`supportedTypes = ['.doc']`), чистый JS без внешних бинарников.
  - `plugins/parser-doc/tsconfig.json`.
- Логика: `word-extractor.extract(buffer)` → `getBody()`, нормализация строк, эвристика заголовков (короткие строки без завершающей пунктуации; ALL CAPS; Title-case) → секции с `headingHierarchy`, абзацы сливаются в `chunkType: 'semantic'`.

Точки регистрации:
- `packages/core/src/config/schema.ts` — `DEFAULT_PARSER_PLUGINS` + `'opendocuments-parser-doc'`.
- `packages/core/src/utils/file-discovery.ts` — расширение `.doc` в `SUPPORTED_EXTENSIONS`.
- `packages/cli/src/commands/init.ts` — пресеты `enterprise` и `all`.
- `docker/hahtn/opendocuments.config.ts` — список `plugins`.

Проверка парсера (в контейнере, на реальных файлах):

## 6. Модуль версионности документов

Реализован сквозной модуль версий ЛНА (закрывает пункт «Версионность (15%)» из ТЗ).

- **Миграция** `packages/core/src/storage/migrations/009_document_version_snapshots.sql`:
  - `document_versions` дополнена колонками `title`, `source_version`, `is_active`;
  - новая таблица `document_version_chunks` — снапшот чанков каждой версии (для диффов).
- **Ядро** `packages/core/src/document/version-manager.ts`:
  - менеджер стал workspace-scoped;
  - `recordVersion` сохраняет снапшот чанков и считает изменения;
  - новые методы `getLatestVersion`, `getActiveVersion`, `getVersionChunks`, `diffVersions`;
  - дифф: LCS по хэшам контента + Jaccard-схожесть слов (порог 0.5) → `added`/`removed`/`modified`/`unchanged`; для больших документов — линейный greedy-фолбэк.
- **Pipeline** `packages/core/src/ingest/pipeline.ts` — передаёт чанки и метаданные в `recordVersion` (версия пишется только при реальном изменении контента / `force`).
- **Сервер**:
  - `packages/server/src/http/routes/versions.ts`: `GET /api/v1/documents/:id/versions`, `.../versions/:version`, `.../versions/diff?from=&to=` (scope `document:read`, проверка workspace);
  - `bootstrap.ts` — `versionManager` в `AppContext`/`WorkspaceServices` (per-workspace), роуты в `app.ts`.
- **Клиент SDK** `@opendocuments/client`: `listDocumentVersions`, `getDocumentVersion`, `getDocumentVersionDiff`.
- **CLI**: `document versions <id>`, `document diff <id> [--from --to]`.
- **Web UI**:
  - компонент `DocumentVersionHistory` (история, бейдж текущей версии, сводка `+ / ~ / −`, построчный diff);
  - явная кнопка «Compare versions» в шапке документа (всегда видна, задизейблена при <2 версий) и ссылка «Compare v1 with v2» в заголовке истории;
  - i18n (en/ko).
- **Тесты**: `packages/core/tests/document/managers.test.ts` (+4 кейса) и `packages/server/tests/http/versions.test.ts` (+5 кейсов).

Проверка: `typecheck` и тесты core (440) / server (80) проходят. Полный `npm run test` падает только на `plugins/parser-doc` (нет тест-файлов — доработка хакатона, к модулю не относится).

## 7. Модуль сравнения двух любых документов

Реализован сквозной функционал сравнения **двух произвольных документов** (не только версий одного документа). Закрывает часть Задачи Б ТЗ — выявление различий/конфликтов между разными ЛНА.

- **Ядро** `packages/core/src/document/version-manager.ts` — метод `compareDocuments(leftId, rightId)`:
  - сравнивает активные (последние) версии двух документов;
  - переиспользует существующий LCS-дифф (`diffChunks`) → `added`/`removed`/`modified`/`unchanged`;
  - дополнительно считает общую схожесть документов `similarity` (Jaccard по word-токенам, 0..1);
  - новый тип `DocumentComparison` (`changes` — `Omit<VersionChanges, 'fromVersion'>`).
- **Сервер** `packages/server/src/http/routes/documents.ts` — `GET /api/v1/documents/compare?left=<id>&right=<id>` (scope `document:read`, проверка workspace, валидация «не с самим собой»; зарегистрирован до `:id`-роута).
- **Клиент SDK** `@opendocuments/client` — `compareDocuments(leftId, rightId)` + типы.
- **CLI** — `opendocuments document compare <leftId> <rightId>`.
- **Web UI** `packages/web/src/components/documents/DocumentCompare.tsx`:
  - два выпадающих списка документов + кнопка «Compare»;
  - сводка: similarity % и `+ / ~ / − / unchanged`, построчный diff;
  - кнопка «Compare documents» в шапке `DocumentsPage`, режим-переключатель;
  - i18n (en/ko): ключи `documents.compare*`.
- **Тесты**: `managers.test.ts` (+2 кейса), `versions.test.ts` (+3 кейса).

Проверка: `typecheck` (core/server/client/cli/web) — ок; тесты core (442) / server (83) — проходят.

## 11. Фикс: `Indexing error / Ollama embed error: 400` на `ДИ_11_993...doc`

Проблема: файл `ДИ_11_993_Упр_по_раб_с_перс_Отд_подб_и_адапт_перс_ГС_без_ПДн.doc` стабильно падал при индексации с `Ollama embed error: 400`.

Причина: в разделе «Должностные обязанности» перечень пунктов разделён `;`, а не `.`. `splitIntoSentences` в `packages/core/src/ingest/chunker.ts` резал текст только по `. ! ?`, поэтому весь список сливался в один «сентенс» ~8900 символов; эмбеддинг такого гигантского фрагмента ронял токенизатор `qwen3-embedding` на стороне Ollama (`connection reset by peer` / `EOF` → `400`). Остальные `.doc` (с точками) индексировались нормально.

Диагностика: воспроизведено локально — короткие фрагменты → `200`, фрагмент 8922 символа → `400`.

Исправление (`chunker.ts`, `splitIntoSentences`):
- `;` (и полная ширина `；`) добавлены как граница предложения для прозы;
- жёсткий лимит `MAX_SENTENCE_CHARS = 1024` с разбивкой по ближайшему пробелу — страховка от любых сверхдлинных предложений.

Проверка: `npx turbo typecheck --filter=opendocuments-core` — ок. Локальный `npm test` не запускается (Node v16.14.2, нужен ≥20) — не связано с фиксом.
