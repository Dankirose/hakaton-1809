## 2. Парсер legacy Word (.doc)

Проблема: `.doc` (OLE/Composite Document) не поддерживался ни одним плагином (есть только `.docx` через mammoth).

Решение — собственный плагин `plugins/parser-doc`:

- Файлы:
  - `plugins/parser-doc/package.json` — зависимости `word-extractor@^1.0.4`, devDep `@types/word-extractor@^1.0.6`.
  - `plugins/parser-doc/src/index.ts` — класс `DOCParser` (`supportedTypes = ['.doc']`), чистый JS без внешних бинарников.
  - `plugins/parser-doc/tsconfig.json`.
- Логика: `word-extractor.extract(buffer)` → `getBody()`, нормализация строк, эвристика заголовков (короткие строки без завершающей пунктуации; ALL CAPS; Title-case) → секции с `headingHierarchy`, абзацы сливаются в `chunkType: 'semantic'`.

Точки регистрации:
- `packages/core/src/config/schema.ts` — `DEFAULT_PARSER_PLUGINS` + `'opendocuments-parser-doc'`.
- `packages/core/src/utils/file-discovery.ts` — расширение `.doc` в `SUPPORTED_EXTENSIONS`.
- `packages/cli/src/commands/init.ts` — пресеты `enterprise` и `all`.
- `docker/hahtn/opendocuments.config.ts` — список `plugins`.

Проверка парсера (в контейнере, на реальных файлах):
- `ДИ_06_4_764...doc` — 9 секций, заголовки определены (`Должностные обязанности`, `Права`, `Ответственность` и т.д.).
- Все 3 `.doc` разбираются без ошибок.

## 7. Команды

```bash
cd hahaton/OpenDocuments-main

# поднять (пересобрать)
docker compose -p smk-opendocuments up -d --build --remove-orphans

# логи
docker logs -f smk-opendocuments-opendocuments-1

# переиндексировать
docker compose -p smk-opendocuments exec opendocuments \
  node packages/cli/dist/index.js index /demo-docs --reindex

# поиск без генерации
docker compose -p smk-opendocuments exec opendocuments \
  node packages/cli/dist/index.js search "запрос"

# вопрос
docker compose -p smk-opendocuments exec opendocuments \
  node packages/cli/dist/index.js ask "вопрос"

# список документов
docker compose -p smk-opendocuments exec opendocuments \
  node packages/cli/dist/index.js document list

# остановить (с удалением данных)
docker compose -p smk-opendocuments down -v
```

## 8. Открытые задачи

- Выжимка/саммари по конкретному документу (Задача Б) — нет готового компонента; retrieval не матчит по имени файла.
- Team mode для демонстрации разграничения доступа.
- Версионность ЛНА — нет из коробки.
- Модель эмбеддингов — `qwen3-embedding:0.6b`; альтернативы (в т.ч. bge-m3) не используются, так как Ollama с ними падает.
