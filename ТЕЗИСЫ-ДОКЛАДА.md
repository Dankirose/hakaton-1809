# Тезисы технического доклада

## Проблема (зачем)
- Контур ЛНА живой: редакции ежемесячно, 20–80 стр./документ, официально-деловой стиль.
- Ключевая боль — **потеря контекста**: сотрудник мыслит ситуациями («повестка в суд — оплачивается?»), документ — категориями («исполнение гособязанностей с отрывом от производства»). Норма физически есть, но «не узнаётся».
- HR тратит до 60% времени на повторяющиеся консультации.

## Решение (что сделали)
- Прототип на базе **OpenDocuments** (MIT, self-hosted RAG-платформа) — требование лицензии заказчика.
- Полностью локальный контур: **Docker + хостовый Ollama**, без внешних API.
  - LLM: `qwen3.5:cloud`, эмбеддинги: `qwen3-embedding:0.6b` (1024 dims, мультиязычная).
  - RAG-профиль `balanced`: rerank + **guard от галлюцинаций** (честное «не найдено»).

## Технические решения (по критериям жюри)

### 1. Качество извлечения (30%)
- Собственный плагин `parser-doc` на `word-extractor` — парсинг legacy `.doc` (OLE), которого нет в стоке (там только `.docx` через mammoth).
- Эвристика заголовков → секции с `headingHierarchy`, чанки `semantic`.
- Ситуационный поиск выдаёт **цитату со ссылкой на пункт** + переформулировку понятным языком.

### 2. Потеря контекста (25%)
- Готовые промпт-шаблоны, переводящие норму в ситуационный ответ «ситуация → действие», без канцелярита, с ограничением «одна страница на документ».

### 3. Версионность (15%) — реализована с нуля (в стоке нет)
- Миграция + `version-manager.ts`: снапшоты чанков каждой версии, `diffVersions` (LCS + Jaccard).
- API `GET /versions`, `/versions/diff`, CLI, SDK, Web UI (история, бейдж текущей версии, «Compare versions»).

### 4. Юзабилити (15%)
- Сравнение **двух произвольных документов** (`compareDocuments`) — выявление конфликтов между разными ЛНА, similarity + построчный diff.

### 5. Безопасность/доступ (10%)
- Workspace-scoped менеджеры, `scope: document:read` на новых endpoint'ах, режим team (в плане).

## Цифры для демо
- Сравнение `ДИ_06 ↔ ДИ_11_993`: similarity ≈ 0.63.

## Планы развития
- Парсинг PDF — не реализован в текущем релизе.
- Парсинг PDF, содержащего изображения (OCR/извлечение текста из картинок) — не реализован.
- Оба направления планируются к выпуску в новом релизе; наработки уже есть.
